# v0.6.0 自动分段与原位显示

快速自动分段模式不再把整个选区合成一条译文：一次 OCR 返回词/行坐标，按相邻基线、字号与行距生成段落；各块独立排队，共享最多两条 HTTP 翻译与缓存。原位快速模式遇到空结果立即撤下对应框；系统 OCR 不可用时仍可使用增强引擎。特殊字体可关闭快速模式，使用清晰优先。

连续定位超过两秒没有新识别帧，会撤下旧覆盖，避免增强引擎卡住时遮挡新画面。旧请求完成后进入回看；只有当前块 ID/版本仍有效时才更新屏幕。临时区默认连续跟译，也可以改为单次快照；快照按用户选择保留。

每区默认最多 12 块（可调 4–24），待译队列最多 24 条，另有两条由该区消费者取出等待/处理。超过上限记录 BLOCK_LIMIT，队列满记录 BLOCK_QUEUE_FULL；不把过量文字合成一个框。段落数量变多会增加 API 请求次数，起始间隔与平台 429 冷却仍适用。

[完整交互与三种模式](USER_GUIDE.md)。以下为 v0.5.0 历史性能记录，其中未实现自动分段的描述仅对应当时版本。

# 速度、短字幕与多区域

v0.5.0，2026-10-20。

## 已减少的等待

旧连续模式至少需要两次 OCR，再发翻译；每轮识别之后额外等待完整扫描间隔。翻译共用串行锁，云端起始间隔固定 1200ms。新字幕会取消上一条请求，短对白可能已经识别到，却没能留下译文。

快速字幕现在每 150ms 独立采样，每区最多缓存最近两帧；优先 Windows OCR，空结果尝试增强识别。增强快速回退降低图像尺寸并只运行一次处理；清晰优先保留原增强字体流程。首次识别即提交，清晰优先的扫描间隔也改为包含识别耗时。

多个区域共用缓存和最多两条同时进行的请求，400ms 最小请求起始间隔可调整。长任务不再独占服务锁。已捕获字幕继续完成并进入回看；晚到的旧结果不会覆盖新译文。如果上一句先返回而下一句尚未完成，会显示“稍早字幕”，原文和译文始终成对。

核心测试让第二帧无限等待，第一帧仍可完成翻译；另一项让第一句晚于第二句返回，验证两句均保留且新显示不被覆盖。这些是流程测试，不依赖公网速度。

固定普通字体练习帧的一次快速读取约 14ms，使用本轮诊断已调用过的 Windows OCR；不含公网/API 生成，不代表其他机器、游戏字体或首次启动的速度。区域大小、模型和网络均影响实际延迟。

## 队列与限流

- 每区两帧采样缓冲，满后保留最新帧，记录 `CAPTURE_BACKLOG`。长时间增强推理期间仍可能漏掉瞬间画面。
- 每区最多八条待译项，另有至多两条被该区消费者取出处理或等待共享服务。待译队列满后跳过最早待译项，记录 `SUBTITLE_QUEUE_FULL`，避免无限堆积。
- 全部区域共享最多两条 HTTP 翻译流程；相同原文共用缓存。
- 快速模式 API 间隔可设 200–5000ms；清晰优先仍为 1200ms。HTTP 429 后依照 Retry-After 或默认冷却；没有自动重试或换供应商，冷却内新字幕不会发请求。
- “对白回看”最近 100 条按本机提交时间排列，只在内存中保留；退出清空，不写日志或诊断报告。

## 多框

“添加框选”最多四个固定区域，例如任务、对白、物品说明、提示。区域间不拼接原文或译文；每区独立识别、判断和显示。主窗口跟随区域下拉框切换，日志标记区域编号。

悬浮框初始放在对应选区旁，空间允许时避开已有框。Ctrl+Alt+L 解锁后可拖动/调整宽度，停止或退出保存位置。恢复的手动位置不会被自动布局挪走；已移出屏幕的位置会重新安排。空间不足时可手动调整，长文本使用滚动区限制高度。

这是手动多区域方案，整窗自动语义聚类尚未加入；位置相近未必属于同一段对白，盲目合并可能拼接任务、菜单或不同人物的文字。

过场可先小范围选中字幕、开启快速模式，并用练习窗口的 0.8 秒自动对白测试实际服务。未采样到的画面无法恢复，公网服务仍需生成时间；已捕获的对白可从回看补看。
