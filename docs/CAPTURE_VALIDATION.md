## 诊断入口

最终自包含单文件测试构建 `0.6.0-capture.1` 已完成工程捕获检查和同批真实游戏素材的本地 Paddle 回放；未在该便携检查中再次调用服务。它是本机测试构建，不是新的稳定版本。核心回归 103 项通过，构建零警告、零错误。

最终回放实现将首帧时间偏移等待归入 `FRAME_WAIT`、图片读取归入 `CAPTURE_OK`。早期回放日志的首次 `CAPTURE_OK` 包含等待偏移，仍保留为原始记录，不用于捕获后端比较。最终便携回放仅验证打包及修正后的计时路径，不覆盖前面的实网样本。

使用应用中的捕获诊断入口，或以参数启动现有应用：

```powershell
LexiLens.exe --diagnostics-capture options.json
```

选项文件中的字段如下；以界面选取真实目标窗口最便于获得本次有效的 HWND。窗口重新创建后应重新选择。

| 字段 | 含义/默认值 |
| --- | --- |
| `Backend` | `Gdi` 或 `Wgc`，分别运行并保存到不同输出目录 |
| `Hwnd` | 本次目标窗口句柄的十进制数；WGC 实际按此 HWND 创建捕获项 |
| `Roi` | `{ "X": 0, "Y": 0.7, "Width": 1, "Height": 0.3 }` 是窗口内字幕区域示例，取值 0–1，不是屏幕坐标 |
| `DurationSeconds` | 30 秒 |
| `Translate` | 默认 `false`，先检查捕获和识别；设为 `true` 才使用本机当前配置的实际翻译服务及其额度 |
| `RecordFrames` | 默认 `false`；显式打开才保存捕获帧，可能包含游戏或私人信息 |
| `SaveEvaluationText` | 默认 `false`；显式打开才在本机保存评估用原文/识别文本，便于人工核对；不应随元数据报告公开 |
| `ReplayManifest` | 可选，输入回放清单路径 |
| `OutputDirectory` | 这次运行的输出目录；不要混合后端、服务或场景 |
| `AllowUnsupportedWindowsOcr` | 默认 `false`；仅为诊断显式尝试未满足包身份条件的 Windows OCR，不改变官方支持范围 |
| `FastMode` / `OcrMode` | 默认 `true` / `Enhanced` |
| `SampleIntervalMs` | 默认 150；这是采样间隔，不是游戏帧时间，也不是端到端延迟 |

GDI 读取可见桌面像素，目标被其他窗口遮挡时会受影响。WGC 获取目标窗口帧后裁剪 ROI，不能将其等同于游戏内部交换链截图。初始化失败、目标最小化、尺寸不符或获取不到新帧时应按失败记录，不要静默换成另一后端并混入样本。

## 可重复回放

先获取获准保存的真实游戏片段及标注，再回放同一批帧。清单示例只说明结构，不提供练习句替代游戏：

```json
{
  "DurationMs": 300,
  "Frames": [
    {
      "File": "frames/000001.png",
      "OffsetMs": 0,
      "SourceOffsetMs": 0,
      "VerifiedOffsetMs": 0,
      "IsRepeatedFrame": false,
      "ReferenceText": null,
      "ScreenRegion": { "X": 100, "Y": 700, "Width": 1200, "Height": 180 }
    },
    {
      "File": "frames/000002.png",
      "OffsetMs": 150,
      "ReferenceText": null,
      "ScreenRegion": { "X": 100, "Y": 700, "Width": 1200, "Height": 180 }
    }
  ]
}
```

`DurationMs` 必填且必须大于末帧 `OffsetMs`；回放按明确的片段总时长结束，不延长尾字幕。`File` 相对清单目录解析，图像为已裁剪的 ROI；`OffsetMs` 为相对开始时刻的采样轮询偏移，必须严格递增。`ScreenRegion` 是该 ROI 对应的物理屏幕位置与尺寸。`Sha256` 可选，用于检查原始 PNG 完整性。

`SourceOffsetMs` 可选，保留原始合成器来源时间；`VerifiedOffsetMs` 可选，保留上次确认该表面的时间，二者均不得晚于采样偏移，来源时间可能早于录制开始而为负。`IsRepeatedFrame: true` 表示重复表面，必须同时提供 `VerifiedOffsetMs`，不能将每次轮询时间冒充新来源帧。省略这些可选时间时回退到采样偏移，只能得到相应近似年龄。

`ReferenceText` 是人工核对的原文，缺失时不能计算字符错误率。实时回放读取当前时间之前的最新帧；较慢处理可能跳过中间帧，这种情况要保留为漏句风险，不能改成离线逐帧等待后宣称实时达标。`run.json` 的 `ocrQuality.sampledFrameCer` 只针对实际读到且有标注的抽样帧，按 `TextProcessing.Normalize`、区分大小写、UTF-16 码元计算，重复读取同帧只计一次；它不包含未读到的整句，不是完整片段的字幕召回率。

回放只能复核已取得帧之后的识别/调度/显示行为，不能测出原始捕获时已经漏掉的字幕，也不能用回放里的图像读取耗时代替 GDI/WGC 捕获耗时。真正比较捕获后端时，应在可重复的同一游戏场景或同一真实片段播放上分别运行两种后端，并另行完成实际游戏测试。

## 时间与计数口径

每条流水线事件保留 `MonotonicTimestamp`；耗时使用 `Stopwatch` 单调时间，墙上时间仅用于查找日志。关联字段包含 `Frame`、`CaptureTimestamp`、`VerifiedTimestamp`、`BlockId`、`Revision`、`FrameAgeMilliseconds`、`FrameVerificationAgeMilliseconds`、`QueueLength`、`DroppedCount`、`OcrEngine`、`FallbackReason` 和 `ColdStart`。以帧和块修订关联各阶段，不把重复 OCR 的最新帧时间重置为字幕第一次出现时间。

| 事件/字段 | 解释 |
| --- | --- |
| `CAPTURE_OK` | 获取并复制 ROI 像素的耗时 |
| `FRAME_WAIT` | 捕获源等待新帧的耗时；GDI 没有异步帧等待，零值不表示游戏零延迟 |
| `FRAME_DEQUEUE` | 识别端等待帧就绪的耗时；另看帧年龄判断拿到的是不是旧帧 |
| `OCR_OK` / `OCR_EMPTY` | 本次实际 OCR 路径耗时，含必要的增强重试；空结果仍需计入 |
| `OCR_FRAME_CACHE` | 复用识别，不属于一次模型推理样本 |
| `BLOCK_STABLE` / `BLOCKS_LOCATED` | 稳定等待及本轮块定位/稳定判断计算 |
| `BLOCK_QUEUE_WAIT` | 文本块进入待译队列至出队 |
| `TRANSLATOR_*` / `API_RATE_WAIT` | 共享翻译并发/合并等待及云端起始限速等待，以日志实际代码为准 |
| `API_REQUEST_SENT` / `HTTP_*` / `API_REQUEST_COMPLETE` | 真正发出请求、响应取得及完整译文解析，彼此不能相加为独立阶段 |
| `API_REQUEST_CANCELLED` | 本次请求随会话结束/取消中止，与服务返回失败分开计数 |
| `BLOCK_REQUEST_STALE` / `BLOCK_QUEUE_REPLACED` / `BLOCK_RESULT_STALE` | 发请求前过时、待译修订替换/容量丢弃、已发请求结果迟到；不能直接等同于漏句 |
| `OVERLAY_VISIBLE` 的 `FrameAgeMilliseconds` | 当前有效译文被应用的显示路径观察到时，距来源帧的年龄。不能证明物理屏幕已经显示，不能称作光子延迟 |
| `OVERLAY_VISIBLE` 的 `DurationMilliseconds` | 有效译文接受至 WPF 呈现回调的阶段耗时，与来源帧年龄分开；仍不是物理屏幕显示时间 |
| `FrameVerificationAgeMilliseconds` | 距最近确认画面有效的时间，与来源表面的年龄分开；静态重复表面不能凭轮询伪造新来源时间 |
| `RequestOrdinal` / `RequestColdStart` | 当前翻译客户端的实际 HTTP 请求序号与首次请求标记；与来源帧/识别的 `ColdStart` 独立 |

WGC 来源时间是合成器渲染该帧的 QPC 时间；GDI 没有相同来源时间，只能以采集开始作近似。因此两者帧年龄基准不同，报告必须保留此限制。`ColdStart` 是来源帧/首次引擎初始化的标签，不能拿来判断 HTTP 是否冷启动；云端阶段使用独立的 `RequestColdStart`。这些标签都不证明操作系统文件缓存或服务端缓存已清空；重复进程的冷/热运行应分别保存。

## 汇总及实际游戏比较

```powershell
python scripts/summarize_capture.py artifacts/capture-gdi/pipeline.jsonl --evidence-kind real-game --output artifacts/capture-gdi/summary.json
```

脚本不读取 `Message`、原文、译文、密钥或截图，仅输出白名单元数据。它优先用 `DurationMilliseconds`，老日志回退到正值 `Milliseconds`；老日志中的零值意义不明，不补作样本。按事件代码及冷/热/未知分组，给出样本数与线性插值 p50/p95。通用 `durationByCode.phase` 采用来源帧标签；HTTP 和请求完成事件另列 `requestDurationByCode.requestPhase`，采用独立的 `RequestColdStart`，缺失时为未知，不能自动沿用帧标签。OCR 推理分布只使用 `OCR_OK` / `OCR_EMPTY`，排除缓存、跳过和错误事件；错误仍保留事件计数。只有 `OVERLAY_VISIBLE` 的成功事件计入有效显示年龄。

每次测试单独存储输出；输入轮换日志时按从旧到新传入文件且避免重复。队列与累计丢弃数报告最大观测值，不能跨不同计数器、区域或重启相加。少量样本的 p95 没有稳定代表性，必须同时阅读样本数。`--evidence-kind` 仅是操作者声明，脚本无法证明素材来自游戏或请求来自真实服务。

实际比较至少包括：静态任务、小字/描边字体、动态背景、一闪即逝字幕、任务文字与字幕并存、窗口移动/缩放、长译文。每个后端使用相同设置和片段，先一次新进程启动，再做热运行；记录游戏、分辨率、显示模式、DPI、CPU/GPU、服务和模型、采样间隔及请求间隔。避免把服务缓存命中与首次请求混为一组。

准确率用人工标注的真实原文计算 CER（替换+删除+插入/参考字符数），另记完整句识别率；译文质量需人工核对专名、数字、任务要求。漏句以真实片段完整字幕清单为分母逐句核对，过期译文以原句消失/替换之后仍出现的译文为依据。游戏帧时间需要同一场景、应用关闭/各后端开启的游戏呈现记录（例如 [PresentMon](https://github.com/GameTechDev/PresentMon)）或游戏自身可靠统计；捕获采样间隔不能代替它。基线相同、持续时间相同，并报告样本数、p50、p95。

## 实际游戏菜单与智谱服务：测量与复测

本轮取得真实游戏菜单的 12.013 秒 ROI 录制，共 74 帧，先按原时间回放并使用真实智谱 `glm-4.5-flash`，随后在同一未切换的难度菜单/开始确认界面分别运行 WGC、GDI 各 15 秒。不是对白、任务过程或过场字幕。硬件为 Ryzen 5 7500F、RTX 2080 Ti；目标窗口物理尺寸 1708×994，ROI 1538×358，归一化位置 `(0.05, 0.58, 0.9, 0.36)`，采样 150ms、快速模式、实际 PaddleOCR，Windows OCR 因无包身份未参与。

[脱敏游戏菜单测量](benchmarks/capture-phase1-game.json)保存全部阶段分组、计数、样本数和限制，不公开游戏图像、原文、标题、路径或密钥。当前复测在 `postFixRuns`，初次记录保留在 `runs`。各次运行的诊断结束标志不表示所有请求或性能目标均成功。

**阶段判断：完成部分验证；一闪即逝的对白/过场尚未验证。**

### 几何修复后的当前结果

本轮发现 Paddle 的 `RotatedRect.Size` 是旋转轴尺寸；水平文字也会返回接近 90° 的角度，直接把其宽高用于屏幕轴会造成文字框异常、段落合并及行序错误。已改用四个角点的屏幕轴外接边界。同一真实检测帧的几何检查，以及水平、90° 等价边界和斜框投影检查均通过；这些检查不使用新的识别结果冒充同帧几何对照。

在相同 74 帧完整素材上重新进行实时评估，实际读到的 12 张标注帧中，原始 OCR 和空间输出 CER 均为 `27/612 = 4.4118%`，完整匹配均为 `0/12`。前后运行会因耗时取到不同的 12 张帧，所以原始 OCR 从 `32/612` 到 `27/612` **不能归因于几何修复提高引擎准确率**。同帧几何检查支持坐标修正的因果结论；复测中空间输出不再额外放大原始 OCR 错误。另一轮开启真实翻译的回放中，两者均为 `32/612 = 5.2288%`，同样说明抽样差异。空格、引号和背景干扰等 OCR 错误仍存在。

### 抽样准确率与已发现错误

较早的首次游戏回放报告把分块拼接送入名为 `ocrQuality` 的统计，得到 `249/561 = 44.3850%`（11 帧）；该字段实际是空间输出 CER，不能当作原始引擎 CER。本次独立评估将两者拆开，原报告保留以便追溯。本节数值均为几何修复之前，未宣称错误已解决。抽样帧指标也不包含未读到的字幕，不能证明完整片段准确率或召回率。

## 官方支持依据

- [Windows.Media.Ocr 支持条件](https://learn.microsoft.com/en-us/uwp/api/windows.media.ocr?view=winrt-26100)：桌面应用要求包身份；安装语言功能与此要求是不同条件。
- [GetCurrentPackageFullName](https://learn.microsoft.com/en-us/windows/win32/api/appmodel/nf-appmodel-getcurrentpackagefullname)：使用系统查询判断当前进程包身份。
- [CreateForWindow](https://learn.microsoft.com/en-us/windows/win32/api/windows.graphics.capture.interop/nf-windows-graphics-capture-interop-igraphicscaptureiteminterop-createforwindow)：按 HWND 创建捕获项，最低 Windows 10 1903。
- [CreateFreeThreaded](https://learn.microsoft.com/en-us/uwp/api/windows.graphics.capture.direct3d11captureframepool.createfreethreaded?view=winrt-26100)：事件在帧池内部工作线程触发，不依赖 UI 的 DispatcherQueue。
- [SystemRelativeTime](https://learn.microsoft.com/en-us/uwp/api/windows.graphics.capture.direct3d11captureframe.systemrelativetime?view=winrt-26100)：合成器渲染帧的 QPC 时间。
- [屏幕捕获与帧生命周期](https://learn.microsoft.com/en-us/windows/apps/develop/media-authoring-processing/screen-capture)：帧归还、按 ContentSize 取有效区域、尺寸变化重建帧池及 HDR 格式注意事项。
- [SetWindowDisplayAffinity](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowdisplayaffinity)：截图排除值从 Windows 10 2004 支持，需要当前进程顶层窗口和 DWM；返回成功不能替代每个后端的像素检查。
- [GetWindowRect](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getwindowrect)：窗口矩形存在 DPI 虚拟化和不可见边框；DWM 扩展可见边界的坐标规则不同。
- [SetForegroundWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setforegroundwindow)：系统可能拒绝恢复前景，必须观察最终状态。
