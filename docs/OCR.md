> v0.6.0：Windows OCR 保留词坐标，PaddleOCR 保留检测行坐标，并映射回原画面。自动分段按基线连接单词，再根据字号/距离合并段落，避免字母下伸部造成一句被拆断。快速定位模式的空结果直接撤层；特殊字体可取消快速模式使用增强识别。下方旧字体基准仍是历史质量测试，不能视作新排版或快速模式的正确率。

> v0.5.0：快速字幕优先使用 Windows OCR，空结果再试增强引擎。取消快速模式可按所选引擎使用增强识别。快速增强回退仅进行一次图像处理，并降低尺寸上限，以缩短耗时；下方字体基准保持原清晰优先流程，不能视作快速模式的正确率。

# 字体识别与实测

v0.4.0 在本机独立子进程使用 PaddleOCR v5 中文/英文模型，保留 Windows OCR。首次 15 秒、后续 8 秒超时终止子进程，能使用系统 OCR 时自动接手；增强结果为空也尝试 Windows OCR。模型随软件分发，不需要 Key、Python、Ollama、显卡或联网下载。CPU 推理限制为 2 个数学线程，截图和图像处理留在本机。其他语言当前使用 Windows OCR。

默认自动模式会放大小字、用局部对比度增强处理灰阶，并在暗背景时反色。模型置信度较低时再用保留颜色的图像识别，选取分数较高的结果。可手动选择原图、暗底亮字或低对比度；同一行碎片会合并，保留段落分行。相同截图复用识别结果。

## 如何检查

框选后点击「检查识别」，对照选区截图与原始 OCR 文字。这次操作不调用翻译服务。若 OCR 原文已错，换翻译平台通常无法可靠修复；可调整识别方式、游戏字号或选区，再测试。

仍不能保证识别所有装饰字体、像素字、被特效覆盖或极小的字。`v/u`、`n/m`、`I/l/1` 等相似字符尤其容易混淆。模型置信度高也可能误识别，不把分数当作正确率，不用 AI 自动编造缺失的游戏专有名词。

## 2026-10-20 合成样张对比

8 个 WPF 生成样张使用固定句子 `Retrieve the ancient relic before dawn.`，图像为 1000×120。每行 33 个字母，共 264 个；字符错误率按编辑距离计算，忽略大小写、空白和标点。Windows 使用 en-US 引擎；增强使用内置 v5 自动模式，CPU 为 AMD Ryzen 5 7500F。

| --- | --- | --- |
| Segoe UI 常规 | 0% | 0% |
| Georgia 斜体 | 0% | 0% |
| Impact 紧缩字体 | 0% | 0% |
| Segoe Script 手写体 | 90.9% | 3.0% |

| 合计 | **22.7%** | **0.8%** |

仍存在实际误字：增强识别把手写体 `Retrieve` 读成 `Retrieue`，把描边的 `dawn` 读成 `dawm`。原始输出和耗时见 [JSON 记录](benchmarks/ocr-fonts-v0.3.0.json)，样张生成代码在 `src/LexiLens.App/OcrFontDiagnostics.cs`。

发布包实测首次调用约 2.3 秒，后续样张单次约 0.6–0.8 秒。此耗时不含扫描等待和翻译延迟；大选区、不同 CPU、动态游戏背景可能更慢。为了稳定，仍需两次相同识别才提交翻译。

这是 v0.3.0 的有限合成回归基线，不能代表所有游戏或预测通用识别正确率。v0.4 保留同一模型并增加进程隔离与超时，端到端耗时还包括子进程启动和 IPC。真实商业游戏、HDR、混合 DPI 和长时间资源占用仍待验证。

## 引擎与依赖

使用 [PaddleSharp](https://github.com/sdcb/PaddleSharp) 封装 PaddleOCR v5，OpenCvSharp 做图像处理，oneDNN/MKL 做 CPU 推理；详见 [第三方说明](THIRD_PARTY_NOTICES.md)。增强加载失败时，有 Windows OCR 则明确提示并切换；缺少 VC++ x64 运行库时可从偏好设置打开微软安装说明。英文/中文增强模式不依赖系统 OCR 语言包。
