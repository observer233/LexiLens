# LexiLens v0.4.0 · 修复等待识别、窗口选择与诊断日志

下载 `LexiLens-v0.4.0-win-x64.zip`，退出旧版，完整解压后运行 `LexiLens.exe`。原有密钥、设置和生词继续使用。Windows x64，自带 .NET 与 OCR 模型。

## 本次修复

- 修复 OCR 结果必须两次完全相同才翻译的等待问题：容忍小幅识别抖动，持续变化三次后提交当前结果。
- 新增“翻译一次”，不经过稳定等待。原文在 OCR 完成后立即显示。
- 增强 OCR 放到独立子进程，首次 15 秒、后续 8 秒超时终止；有 Windows OCR 时接手。增强结果为空时也尝试系统 OCR。
- 空识别、近乎全黑截图、引擎回退和 HTTP 错误分别显示，不再统一停留在等待文案。

## 窗口与界面

- “选择窗口”：移到游戏上显示吸附边框，单击选择整个可见窗口；保留手动框选。
- 新增 Ctrl+Alt+W 选窗口、Ctrl+Alt+F 单次翻译；原有快捷键保留。
- 浅色 Windows Fluent 界面，移除宣传式文案；首次引导只保留服务、区域、单次测试三步。
- 简化平台配置，模型和 API Key 直接可见，政策说明与高级地址可展开。

## 诊断与日志

主界面分别显示：截图 → 文字识别 → 文字判断 → 翻译服务 → 悬浮显示。

“诊断与日志”可查看耗时、字符数、错误代码与 HTTP 状态，测试当前服务、检查识别、切换 Windows OCR，并导出 JSON 报告。日志写入本机并轮换，重启后可读；不记录游戏原文、截图、密钥、窗口标题或服务地址。

## 建议的验证顺序

服务测试成功 → 选择窗口/字幕 → 翻译一次 → 确认原文和译文 → 连续翻译。

如果仍没有译文，打开诊断页查看具体步骤，导出报告用于排查。连接测试只验证固定短句，不代表游戏截图和 OCR 已完成。

## 验证范围

73 项核心测试通过。相同的交替 OCR 数据运行 700ms，v0.3 原代码请求 0 次，修复版 1 次。桌面诊断覆盖实际截图、独立进程 OCR、MyMemory 翻译、单次流程、窗口选择、故意卡死后的超时回退、取消和日志导出。

已检索并参考 Translumo、LunaTranslator、Game2Text、SubLens、Pot、WPF UI 的流程或布局；[调研记录](https://github.com/observer233/LexiLens/blob/main/docs/RESEARCH.md)。[故障分析](https://github.com/observer233/LexiLens/blob/main/docs/BUG_ANALYSIS.md) 区分已复现代码缺陷和仍需日志确认的现场问题。
